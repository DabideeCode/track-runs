# Track Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single-page wooden toy train diorama builder: build on a 16×16 grid and play with a train on the tracks you built.

**Architecture:** Pure TypeScript domain modules (`src/game/*`) hold the grid maths, placement rules, connections, track paths and the train simulation, all unit-tested. One Zustand store (`src/store/gameStore.ts`) owns game state and actions. The UI and the test hook call the same actions, so validation and sounds are identical. The R3F scene (`src/scene/*`) renders only 3D. HTML overlays (`src/ui/*`) render all controls.

**Tech Stack:** Node 22.17.0, npm, Vite 8, React 19, TypeScript, Tailwind 4 (`@tailwindcss/vite`), shadcn/ui (Radix base), three 0.186, @react-three/fiber 9, @react-three/drei 10, Zustand 5, nanoid, tone (lazy-loaded). Dev: Vitest + jsdom.

**Spec:** `requirement.md` (single source of truth) and `docs/superpowers/specs/2026-10-29-track-decisions.md` (calls D1–D30 for gaps).

## Global Constraints

- TypeScript; React with Vite; Tailwind CSS with Radix UI primitives via shadcn/ui; Three.js via @react-three/fiber; @react-three/drei; Zustand.
- Extra runtime deps only: `@react-spring/three`, `howler`, `nanoid`, `tone`. No physics engine. No backend. (shadcn's own support packages — `@radix-ui/*`/`radix-ui`, `class-variance-authority`, `clsx`, `tailwind-merge`, `lucide-react`, `tw-animate-css` — count as "shadcn/ui".)
- A single Zustand store holds the §9 `GameState` (exact names/types). Canvas renders only the 3D scene; all controls are HTML overlays.
- The grid is 16×16; tile (gx, gz) has its centre at (gx − 7.5, gz − 7.5). North = −Z, east = +X. Clockwise rotation viewed from above ⇒ `rotation.y = −rad(rotation)`.
- localStorage keys: `wooden-diorama:v1` (SaveFile `{version:1, dioramas}`) and `wooden-diorama:audio`.
- Test hook `window.__DIORAMA__` is exposed only if `import.meta.env.DEV` or the URL has `?test=1`. Reason codes: `occupied`, `out_of_bounds`, `on_track`, `station_limit`, `no_station`, `play_mode`, `not_found`. Sound names: `pickup`, `place`, `move`, `rotate`, `delete`, `snap`, `invalid`, `ui`, `whistle`, `chug`, `bump`.
- The browser tab title and main menu heading are "Track".
- Performance: DPR capped at 1.5; ≤1 shadow-casting light, shadow map ≤2048; shared geometry/materials; ≥30 fps with 100 pieces at 1080p.
- Palette: soft, warm, low-saturation colours (cream, honey wood, sage, dusty blue, terracotta); no pure #000/#fff, no neon. Wood roughness ≥ 0.6.
- Overlay panels cover ≤25% of the viewport in Build mode; visible focus rings; accessible names on all controls.
- `npm install`, `npm run dev`, `npm run build` (with type-check) all succeed; no console errors in normal use.

## Review Focus

1. **Corrupt localStorage** (invalid JSON, wrong `version`, non-array, a piece out of range or overlapping, bad rotation): the menu still renders, the bad entry is skipped and `console.warn` is logged. Tests are in Task 3.
2. **Degenerate layouts for the train** (lone station; station plus buffer; a curve that leads nowhere; closed loop): no NaN positions, no leaving the track, exactly one `bump` per arrival, and infinite running on a loop. Tests are in Task 2.
3. **Shortcuts while typing** (Backspace or R inside the rename input; keys while a dialog is open) must not touch pieces. A `shouldHandleShortcut` test is in Task 4.
4. **Moving a piece onto its own tiles** (including a hill shifted by one tile so it overlaps its old footprint) is valid. A test is in Task 1.
5. **Name edge cases** (whitespace-only, 41 chars, "Untitled diorama 2" taken but not "Untitled diorama"): rejected or numbered correctly. Tests are in Task 3.

### Task 2: Track paths and train simulation (pure)

**Files:** Create `src/game/trackPath.ts`, `src/game/train.ts`. Tests: `src/game/__tests__/trackPath.test.ts`, `train.test.ts`.

**Interfaces:**
- `trackPath.ts`: `pathLength(type) → number` (straight/station/tunnel 1, curve π/4, buffer 0.75); `samplePath(piece, u) → {x, z, heading}` in **world** coords, where `heading` is the yaw of the canonical +u tangent (D13); `pathEnds(piece) → {startDir: Dir, endDir: Dir|null}` (world dirs of the u=0 and u=L edges; buffer endDir null = dead end).
- `train.ts`:
  ```ts
  interface TrackCursor { pieceId: string; u: number }       // u in [0, L]
  interface TrainSim {
    cursor: TrackCursor; facing: 1 | -1;   // +1 = loco faces +u
    v: number;                              // signed, +forward, tiles/s
    autoDir: 1 | -1; pauseLeft: number; atEnd: boolean; wasMoving: boolean;
  }
  type TrainEvent = 'chug' | 'bump';
  createTrain(pieces, startFacing) → TrainSim | null        // null without station; loco at station u=0.5; facing 0 ⇒ facing=-1
  walk(pieces, cursor, distance, sign) → { cursor, moved: number, blocked: boolean }  // follows connections across pieces
  distanceToEnd(pieces, cursor, sign, max=12) → number
  stepTrain(sim, pieces, dt, input: {drive:'auto'|'manual'; fwd:boolean; rev:boolean}) → TrainEvent[]  // mutates sim
  trainPoses(sim, pieces) → [{x,z,heading}, …3]               // loco + 2 carriages (D12/D14 offsets 0, 0.95, 1.85)
  trainInfo(sim) → { pieceId, progress, moving, direction, speed }   // getTrain() shape
  ```
