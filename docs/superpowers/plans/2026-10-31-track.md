# Track Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Track, the wooden train diorama builder in `requirement.md`, complete against Section 13.

**Architecture:** A pure `src/game` core (rules, paths, simulation, store) that both the UI and the test hook call, an instanced R3F scene that only reads it, and an HTML overlay.

**Tech Stack:** TypeScript, React, Vite, Tailwind v4, Radix via shadcn/ui, three + R3F + drei, Zustand, howler, nanoid. Vitest and Playwright (system Chrome) for tests.

**Spec:** `requirement.md`, with decisions in `docs/superpowers/specs/2026-10-31-track-design.md`.

## Global Constraints

- Runtime dependencies only from Section 3 plus shadcn's own parts (see the design doc).
- Rotation is clockwise from above: `mesh.rotation.y = -deg * PI / 180`.
- Tile centre: `x = gridX - 7.5`, `z = gridZ - 7.5`. North is -Z, east is +X.
- DPR cap 1.5. One shadow light, map at most 2048. Materials: wood and paint roughness >= 0.6.
- Storage keys `wooden-diorama:v1`, `wooden-diorama:audio`. Test ids exactly as Section 10.1.
- No pure black, pure white or neon. Overlay at most 25% of the viewport in Build mode.

## Review Focus

- Dragging the only station away and dropping it invalid: it returns, and no second station can sneak in. Test in Task 2.
- Corrupt storage (bad JSON, wrong shape, one bad entry): menu survives, good entries still list, saving does not destroy them. Test in Task 4.
- Very short track (lone station, station at a dead end): train neither crashes nor gets stuck in a NaN state. Test in Task 3.
- Key handling while typing in the rename input or with a dialog open: R, F, Delete and Backspace must not edit the diorama. Test in Task 8.
- Leaving Play with a key held, or the window losing focus while W is down: train must not keep running. Test in Task 3.
